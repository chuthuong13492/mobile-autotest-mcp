# ADR-0012: CI provider selection process

- **Status:** **Proposed**. The decision is made at the Phase 0 exit (DISC-004). Until then, CI work is limited to the provider-neutral CI-001.
- **Date:** 2026-10-22
- **Deciders:** Principal Architect, DevSecOps Engineer, Mobile Platform owner (organization)
- **Supersedes / Superseded by:** —

## Context

CI must execute approved plans, collect artifacts, and publish checks or statuses (G-12, FR-042). The evidence gathered so far:

- The reference organization uses **GHES** (`ghe.coxautoinc.com`) with **self-hosted Linux** runners for Flutter tests ([RL-A06](../research-log.md#b-autotrader-reference-repository-read-only-inspection-2026-10-22), [RL-A07](../research-log.md#b-autotrader-reference-repository-read-only-inspection-2026-10-22)).
- iOS builds run only on **Bitrise** macOS (`osx-xcode-26.3.x`) ([RL-A08](../research-log.md#b-autotrader-reference-repository-read-only-inspection-2026-10-22)).
- GitHub-hosted runners are not available on GHES ([RL-026](../research-log.md#rl-026--github-hosted-runners-on-ghes)).
- Published list prices for 2026-10-22 are recorded in [RL-027](../research-log.md#rl-027--ci-pricing-published-list-prices-not-quotes). Whether Bitrise and Codemagic support GHES is not stated on their pricing pages.

## Decision (proposed)

### Selection criteria

Each criterion is scored 1–5 and multiplied by its weight. The scoring sheet lives in [local-and-ci-execution §CI provider comparison](../local-and-ci-execution.md#ci-provider-comparison).

| Criterion | Weight |
|---|---|
| GHES compatibility (triggers, checks/statuses, token model) | 5 |
| macOS/iOS capability when needed (v1.1+) | 3 |
| Flutter host-test support on Linux (v0.2 need) | 5 |
| Runner availability and concurrency | 3 |
| Security and isolation (ephemeral runners, fork-PR secret handling, OIDC) | 5 |
| Secret management | 4 |
| Caching (Flutter SDK, pub cache) | 3 |
| Artifact support and retention | 3 |
| Reporting integration (checks/status) | 4 |
| Maintenance effort | 3 |
| Cost at the expected workload | 3 |
| Operational reliability and fit with existing org infrastructure | 4 |

### Provisional recommendation (not a decision)

For **v0.2/v1.0**, which need only Flutter host tests, use **GitHub Actions on GHES with the organization's existing self-hosted Linux runners, configured as ephemeral runners**.

Reasons:

- The PR, checks and `GITHUB_TOKEN` all live on the same host.
- No new vendor is introduced.
- Linux is enough for host Flutter tests.
- The organization already operates these runners.

For macOS work in **v1.1+**, choose between self-hosted Mac runners and Bitrise, since the organization already uses Bitrise. Both are evaluated in DISC-004.

### Evidence required to decide

1. The GHES version and the Actions feature set at `ghe.coxautoinc.com`: `checks: write` for `GITHUB_TOKEN`, OIDC support, and ephemeral or JIT runner registration (OQ-07).
2. Whether the self-hosted runner pool can be made ephemeral, or wiped between jobs, for jobs that run PR code.
3. Bitrise and Codemagic GHES integration capability, and contract pricing (OQ-10).
4. Organizational security policy for running untrusted PR code on shared runners.
5. A measured run of the fixture plus an Autotrader subset on the candidate provider: duration and cache effectiveness.

### Neutrality

Whatever is chosen, provider-specific code lives only in a provider module behind `CiEnvironmentPort` (CI-001). The core is never coupled to a provider.

## Alternatives considered

The candidates are GitHub Actions on GHES with self-hosted runners, Bitrise, Codemagic, and self-hosted Mac runners. The comparison table is in [local-and-ci-execution.md](../local-and-ci-execution.md#ci-provider-comparison).
