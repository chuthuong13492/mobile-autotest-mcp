# ADR-0015: Dependency-boundary enforcement with dependency-cruiser

- **Status:** Accepted (planning)
- **Date:** 2026-10-22
- **Deciders:** Principal Architect
- **Supersedes / Superseded by:** —

## Context

Several architectural guarantees depend on import rules:

- the gate does not depend on planning ([ADR-0005](ADR-0005.md))
- adapters cannot spawn processes ([ADR-0009](ADR-0009.md), [ADR-0014](ADR-0014.md))
- no package depends on the apps
- domain code is SDK-agnostic ([ADR-0001](ADR-0001.md))

Code review alone cannot keep these guarantees in place.

## Decision

1. Use **dependency-cruiser**, pinned as a dev dependency, with a committed `.dependency-cruiser.cjs` at the repository root. It runs in the repository's CI on every PR as a required check (OPS-003).
2. **Mandatory rules**, all with severity `error`:

   | Rule id | Rule |
   |---|---|
   | `no-circular` | No cycles between packages or modules. |
   | `no-apps-import` | `packages/**` must not import `apps/**`. |
   | `allowed-package-deps` | Each package may import only the packages listed in [architecture.md §Packages](../architecture.md#packages-and-dependency-rules). This is generated from a single `boundaries.json`. |
   | `coverage-gate-not-planning` | `packages/coverage-gate/**` must not import `packages/planning/**`, directly or transitively. |
   | `adapters-isolated` | No `packages/adapter-*` may import another `adapter-*`. |
   | `adapters-no-side-effects` | `packages/adapter-*`, `planning`, `coverage-gate` and `analysis` must not import `node:child_process`, `node:fs`, `node:net`, `node:http(s)`, `http2`, `dgram`, `tls` or `dns`. |
   | `pure-units-no-network-libs` | The same pure units must not import HTTP client libraries (`undici`, `node-fetch`, `axios`, `got`). |
   | `only-exec-spawns` | Only `packages/exec` may import `node:child_process`. |
   | `only-github-network` | Only `packages/github` may import `@octokit/*`. |
   | `sdk-only-in-app` | Only `apps/mcp-server` may import `@modelcontextprotocol/*`. |
   | `no-llm-sdks` | No package imports LLM SDKs (supports [ADR-0004](ADR-0004.md)). |
   | `no-deep-imports` | Cross-package imports go through a package entrypoint only: `src/index.ts`, or the optional test-only `src/testing/index.ts` (fakes, samples and contract kits). |

3. The `boundaries.json` file is the machine-readable twin of the architecture table. A CI script checks that the two agree (OPS-003).

## Alternatives considered

| Option | Why not chosen |
|---|---|
| eslint-plugin-boundaries | Viable, but weaker at checking transitive dependencies and Node built-ins. |
| TypeScript project references only | Prevents some imports, but cannot express the built-in bans. |
| Nx module boundaries | Would require adopting Nx. |

### Implementation status (2026-10-23, OPS-003)

Implemented in `.dependency-cruiser.cjs`, which generates one `allowed-package-deps:<unit>` rule per workspace unit from `boundaries.json`.

**Gotcha.** `node_modules` must not be in dependency-cruiser's `exclude` option. Excluding it hides every npm import, so the SDK, Octokit and LLM rules would silently never fire. It is only listed in `doNotFollow`.

**Verification.** `pnpm depcruise` runs the rules plus `scripts/check-boundaries.ts`, which checks that `boundaries.json` matches every `package.json` and the architecture table. `pnpm depcruise:negative` (`scripts/check-boundaries-negative.ts`) proves that each rule fires on a deliberately violating fixture in `test/boundaries-negative/`, fails if any rule is never exercised, and checks the ESLint non-literal dynamic import rule.

## Consequences

- An intentional boundary change requires editing `boundaries.json`, the architecture doc and this ADR together.

## Risks

- Rule gaps, for example dynamic `import()` with computed specifiers. These are mitigated by a lint rule that forbids non-literal dynamic imports.

## Verification and revisit triggers

- **Verification:** OPS-003 includes negative fixtures: deliberately violating files in a test directory that must fail the check.
- **Revisit when** the tool goes unmaintained.
