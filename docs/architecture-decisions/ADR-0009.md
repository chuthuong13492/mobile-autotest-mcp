# ADR-0009: Platform adapter capability model with injected ports

- **Status:** Accepted (planning)
- **Date:** 2026-10-22
- **Deciders:** Principal Architect, Mobile Automation Architect
- **Supersedes / Superseded by:** —

## Context

Flutter, React Native, native iOS, native Android and Appium differ in several ways:

- their test levels
- the runners they use
- whether they need a device
- their result formats
- whether they need a macOS host

Forcing identical behavior onto all of them would hide those real limits. Adapters also build commands, which makes them a security-sensitive part of the system.

## Decision

1. `packages/adapter-sdk` defines a `PlatformAdapter` interface. The full TypeScript sketch is in [platform-adapters.md §Adapter interface](../platform-adapters.md#adapter-interface). It has these methods:

   | Method | Purpose |
   |---|---|
   | `id`, `version` | Identify the adapter |
   | `detect(ctx)` | Returns `DetectionResult` with confidence and evidence |
   | `capabilities(ctx)` | Returns `CapabilitySet` |
   | `inventory(ctx)` | Returns `InventoryFragment` |
   | `resolveTargets(plan, inventory)` | Maps test cases to targets |
   | `buildExecution(request)` | Returns `ExecutionSpec[]`: typed argv, cwd, env needs, expected outputs |
   | `parseResults(outputs)` | Returns `NormalizedResult[]` |
   | `evidenceHints(outputs)` | Points at artifacts to collect |
   | `classifySignals(results)` | Returns failure signals |
   | `cleanup(ctx)` | Releases resources |

2. **Capabilities are explicit data.** Each capability records:
   - the supported test levels: `unit`, `widget/component`, `integration`, `e2e`
   - the host OS requirement: `any`, `macos`, `linux`
   - device needs: `none`, `simulator`, `emulator`, `physical`
   - the selection granularity: `file`, `name`, `tag`, `scheme`, `class`
   - the result formats
   - cancellation semantics
   - known limitations

   Eligibility (FR-014) is computed from these capabilities, never by assuming parity between platforms.
3. **Injected ports only.**
   - Adapters receive `WorkspaceReader` (bounded, policy-checked reads) and `ExecutionPlanner` (validation only).
   - Adapters **do not spawn processes**. They return `ExecutionSpec` data. `execution` passes those specs through `policy` and hands them to `exec`.
   - Adapters may not import `node:child_process`, `node:fs` or network modules. This is enforced by dependency-cruiser ([ADR-0015](ADR-0015.md)).
4. **Registry and selection.** `inspect_project` runs `detect` on every registered adapter. Several adapters can match the same repository. Flutter projects, for example, also contain native iOS and Android folders. Selection is per test target, and goes to the adapter that owns the target's runner.
5. **Contract test kit.** `adapter-sdk` ships a reusable suite that every adapter must pass. It checks determinism, ExecutionSpec validity against policy schemas, parser robustness against malformed and oversized output, and cleanup idempotency.

## Alternatives considered

| Option | Why not chosen |
|---|---|
| Adapters that execute directly | They would bypass central policy and spread spawn logic around. |
| A single generic "command template" adapter | Simple, but it turns into arbitrary command execution and can't parse rich results. |
| Appium as the universal layer | Wrong fit for unit and widget tests, and slow ([ADR-0011](ADR-0011.md)). |

## Consequences

- Adding a platform means adding a package plus policy entries for its executables. Core stays unchanged (NFR-007).
- Adapters are pure and deterministic, which makes them easy to test with recorded fixtures.

## Risks

- Changes in result formats (Xcode, Flutter protocol), tracked as [RK-07](../risks-and-open-questions.md#rk-07). Parsers are versioned, and adapters record the format and protocol version in the evidence.

## Verification and revisit triggers

- **Verification:**
  - ADP-001 contract kit
  - the OPS-003 import ban
- **Revisit when** an adapter genuinely needs streaming interaction with a runner, such as Appium sessions. Add a `SessionPort` through an ADR.
