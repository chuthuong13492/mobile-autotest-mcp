# ADR-0004: No server-side LLM in Release 1

- **Status:** Accepted (planning)
- **Date:** 2026-10-22
- **Deciders:** Principal Architect, Security Engineer
- **Supersedes / Superseded by:** —

## Context

Test planning needs judgment: reading prose and judging ambiguity. Authorization, coverage and execution need determinism and auditability. MCP Sampling, which would let a server call the client's LLM, is deprecated in the 2026-07-28 specification ([RL-001](../research-log.md#rl-001--current-mcp-specification-revision)). A server-side LLM call would also put an unverifiable, non-deterministic component inside the trust boundary, and it adds credential and cost concerns.

## Decision

1. In Release 1 the MCP server **never calls an LLM**, neither directly nor through Sampling.
2. **The agent, guided by the Skill, drafts** the requirements and the test plan.
3. The server's `extract_requirements` performs deterministic parsing and merges agent-supplied items, tagging their provenance.
4. The server's `generate_test_plan` deterministically does all of the following:
   - validates the draft against the schema
   - normalizes text fields (trim, Unicode NFC, collapse whitespace)
   - assigns stable IDs
   - resolves test targets against the persisted inventory
   - computes risk tiers with the rule model
   - determines eligibility
   - computes the canonical plan hash
   - persists an immutable plan version
5. Agent-written prose (rationales, narrative) is stored as **untrusted, display-only** content. The gate and the authorization logic never base a decision on it, and it is excluded from the hash where it is purely presentational ([data-model §Plan hash](../data-model-and-artifacts.md#plan-hash-specification)).
6. **Extension point:** a future `PlanSuggester` port in `planning` may host server-side or Sampling-based suggestions. Any suggestion would still go through the same deterministic validation and an independent gate. This requires a new ADR.

## Alternatives considered

| Option | Why not chosen |
|---|---|
| A server-side LLM generates the plan | Non-deterministic, harder to audit, adds credential and cost handling, and enlarges the injection surface. |
| MCP Sampling | Deprecated in 2026-07-28, and client support varies. |
| The server generates plans from templates only | Too rigid for prose PRs. The agent is better at interpretation, and the server's role is to check its work. |

## Consequences

- Plan quality depends on the agent and the Skill. The gate exists to catch gaps independently (ADR-0005).
- The same plan can be produced by a human or a different agent, because the input format is open.

## Risks

- [RK-10](../risks-and-open-questions.md#rk-10): over-trust in agent drafts (rubber-stamp approvals). Mitigated by gate rules, AL2+ approval for `needs_review`, and report limitations.

## Verification and revisit triggers

- **Verification:** OPS-003 dependency rules forbid LLM SDK packages in `packages/*`. A grep check in CI forbids `sampling/createMessage`.
- **Revisit when** product leadership requests autonomous plan generation, or a deterministic-validation-plus-LLM design is proposed.
