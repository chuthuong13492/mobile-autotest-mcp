# ADR-0014: Shell-free, policy-governed execution

- **Status:** Accepted (planning).
  - **Update 2026-10-23 (EXE-001, EXE-004):** `exec` re-validates every spec and rebuilds the environment before each spawn, spawns with `shell: false` in a new process group with stdin closed, and caps output through pipes with a single truncation marker. `ulimit`-style limits are **not** applied in v1.0: Node cannot set rlimits for a shell-free child on macOS. `ExecPort.capabilities.rlimits` reports `false`, and nothing claims otherwise.
- **Date:** 2026-10-22
- **Deciders:** Security Engineer, Principal Architect
- **Supersedes / Superseded by:** —

## Context

The system executes build and test tooling chosen from repository content. That content is untrusted, and so are the agent's instructions where they derive from it.

A generic shell tool would let prompt injection turn into arbitrary command execution. The MCP specification requires servers to validate inputs and implement access controls ([RL-002](../research-log.md#rl-002--tool-annotations-are-untrusted-hints)). Running a test suite still runs repository code, so OS-level isolation is partial at best.

## Decision

1. **No general command tool.** No MCP tool accepts a command string, executable path or argv. `run_tests` accepts `planId`, `planHash`, `targets[]` (TestTarget IDs from the plan) and typed options. These options include the timeout, retry overrides within policy, device IDs and evidence options.
2. **Adapters produce specs, not processes** ([ADR-0009](ADR-0009.md)). An `ExecutionSpec` contains:
   - `executable`: a logical name such as `flutter`
   - `args[]`: typed tokens produced by the adapter's builder
   - `cwd`
   - `envNeeds[]`
   - `expectedOutputs[]`
   - `timeoutMs`
3. **`policy` validates each spec:**
   - The logical executable maps to allowlisted absolute paths, resolved at startup and pinned by realpath and an optional SHA-256. Resolution happens through configuration, never through PATH lookup at spawn time.
   - Each executable has an **argument schema**: allowed subcommands, flags, and the value patterns for each flag. Path arguments must canonicalize inside the workspace or the run directory.
   - `cwd` must be inside an allowlisted workspace.
   - The environment is built from a minimal base (`PATH` = the allowlisted directories, `HOME`/`TMPDIR` = run-scoped where possible, locale) plus the allowlisted variables plus secret references resolved at spawn time.
4. **`exec` spawns with `shell: false`** and `detached: true`, so the child gets its own process group. Its stdio goes to files with byte caps. `exec` re-validates the spec against policy, because the decision from step 3 is not trusted on its own. Inherited stdin is closed.
5. **Resource controls:**
   - wall-clock timeouts
   - output caps (default 50 MiB per stream, after which output is truncated with a marker)
   - a per-run disk quota (default 2 GiB), checked periodically
   - a concurrency limit
   - `ulimit`-style limits where the platform supports them, behind the `ExecPort`
6. **Network.** v1.0 does not restrict a test process's network at the OS level. The default policy forbids network-fetching subcommands such as `pub get` unless they are explicitly enabled with lockfile enforcement (SR-014). This is a documented residual risk; see [security-threat-model](../security-threat-model.md#residual-risks).
7. **Isolation.** An optional macOS `sandbox-exec` profile or Linux namespaces are **out of scope for v1.0**. They are documented as hardening options and not claimed as protection.

## Alternatives considered

| Option | Why not chosen |
|---|---|
| A shell with escaping | Brittle and a classic injection vector. |
| Allowlisting command strings | Too coarse; argument smuggling remains possible. |
| Containers for every run | Not viable for iOS or simulators on macOS, and heavy for local use. It could be added later for Linux CI. |

## Consequences

- Each new runner flag needs a policy schema update. That is deliberate friction.
- Commands are reproducible from recorded specs, which serves audit and CI parity.

## Risks

- Test code itself can be malicious (T-02). The mitigations are a reduced environment, no secrets by default, and isolated runners in CI. The residual risk is documented.

## Verification and revisit triggers

- **Verification:**
  - SEC-001 injection corpus: shell metacharacters in test names, path traversal in targets, env smuggling, PATH hijack attempts
  - OPS-003 rule: only `packages/exec` imports `node:child_process`
- **Revisit when** remote or multi-tenant execution is introduced, at which point mandatory sandboxing is required.
