# ADR-0008: Filesystem artifact store plus SQLite index

- **Status:** Accepted (planning). **Update 2026-10-23 (DISC-008):** the driver sub-decision is made. `node:sqlite` is used ([RL-033](../research-log.md#rl-033--nodesqlite-evaluation)), and OQ-19 is closed.
- **Date:** 2026-10-22
- **Deciders:** Principal Architect
- **Supersedes / Superseded by:** —

## Context

The system needs durable storage for:

- plans
- decisions
- approvals
- runs and attempts
- per-test results
- artifact metadata
- audit events

Artifacts such as logs, JUnit files and screenshots can be large binary files. The first deployment is local-first and single-user, plus CI jobs. The candidate SQLite drivers are:

- **Built-in `node:sqlite`:** "Release candidate" (Stability 1.2) on Node 26, experimental on Node 24 ([RL-012](../research-log.md#rl-012--nodesqlite-stability)).
- **A native addon such as `better-sqlite3`:** carries native-build and supply-chain cost.

## Decision

1. **Layout.**
   - Data root: `~/.autotest/` (overridable by `AUTOTEST_HOME`), with mode `0700`.
   - Artifacts: `~/.autotest/runs/<runId>/…`, laid out as specified in [data-model §On-disk layout](../data-model-and-artifacts.md#on-disk-layout).
   - Plans: immutable JSON snapshots at `~/.autotest/plans/<planId>/<planHash>.json`.
   - Approvals: `~/.autotest/approvals/`, with mode `0600`.
   - Data never lives inside target repositories (SR-019).
2. **Index.** A single SQLite database, `~/.autotest/autotest.db`, runs in WAL mode with `busy_timeout=5000` and `foreign_keys=ON`. Its schema is versioned with forward-only migrations (STO-002).
3. **Write protocol and consistency.**
   1. Write the file to `*.tmp` in the target directory.
   2. `fsync` the file.
   3. `rename` it into place.
   4. `fsync` the directory.
   5. Insert or update the SQLite row in a transaction that records the file's SHA-256.

   On startup, STO-004 reconciles the two sides:
   - A file with no row is indexed only if it is valid and its checksum matches; otherwise it is quarantined.
   - A row with no file is marked `missing`, and the affected run gets the limitation `artifact_missing`.
4. **Driver.** All SQL access goes through a `SqlPort` in `packages/storage`.
   - **Default proposal:** `node:sqlite` on Node 26. It has no native build and no third-party code.
   - **Fallback:** `better-sqlite3`, if DISC-008 finds blocking gaps. Examples would be experimental-warning noise on Node 24, missing features, or performance problems.

   The decision is recorded by updating this ADR at the Phase 0 exit.
5. **Retention.** Run artifacts are kept 14 days and audit records 90 days, with a total cap of 5 GiB. Approvals are kept for 90 days after expiry. All of these are configurable (NFR-012). Cleanup never deletes the data of a non-terminal run.
6. **Migration path.** The `RunStore` and `ArtifactStore` ports allow replacement with Postgres plus object storage when the extraction triggers in [ADR-0002](ADR-0002.md) occur.

### Driver decision (2026-10-23)

Use **`node:sqlite`** behind `SqlPort`. On Node 24.22.1 and 26.12.1 it passed every required check without a warning:

- WAL mode, `busy_timeout`, foreign keys and rollback
- 50k inserts in about 20 ms
- two processes each writing 2,000 transactions with zero busy errors and `integrity_check=ok`

Node 22 prints an `ExperimentalWarning`, but Node 22 is outside the support matrix. `better-sqlite3` is not adopted, so there is no native addon or install script.

## Alternatives considered

| Option | Why not chosen |
|---|---|
| JSON files only | No efficient queries, and poor concurrency. |
| Postgres | Too heavy for local-first use. |
| Artifacts stored as SQLite BLOBs | Makes the database large and hurts streaming and retention. |

## Consequences

- Two stores must be kept consistent. The write protocol and the reconciliation step cover this.

## Risks

- [RK-11](../risks-and-open-questions.md#rk-11): SQLite contention when multiple sessions run at once.
